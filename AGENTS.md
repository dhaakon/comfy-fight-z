# Hackathon project instructions

- Keep generation sources in `comfyui/`, game/builder source and tools in `build/`, and generated runs/exports in `output/`. The user also requested a fourth root folder, `example/`, containing a portable complete workflow, example configuration, build runner, and a reviewed fictional asset bundle that can build a real game after installation. Keep root metadata and the npm wrapper at the root; do not restore the old mixed layout.
- Main workflow JSON files live in `comfyui/workflows/`. Accepted runtime source files live in `build/public/`; normal builds write and serve `output/game/`. Keep generated source bundles in `output/test-runs/`, CLI staging in `output/assets/generated/`, independent exports in `output/exports/`, and reports/backups in `output/diagnostics/`. `output/private-archive/` is ignored, never served and never copied into an export.
- Use cloud-hosted models for all model inference in this hackathon, including image generation. Build ComfyUI workflows with cloud/API model nodes rather than local model checkpoints.
- The included `example/` must build from its checked-in assets without a ComfyUI server, cloud login or paid generation. Regeneration is an explicit separate workflow with a fresh output directory and reviewed spending estimate. Preserve lossless sprite/chroma pixels when packaging source images, update manifest paths/hashes after conversion, and keep original generation runs under ignored `output/`.
- Do not download local model weights or configure local inference for this project unless the user explicitly changes this preference.
- This cloud-model preference does not itself authorize paid runs; follow the connected tools' spending-consent requirements.
- Build Comfy Fighter Z, an anime fighting-game asset factory and browser game. Keep the existing combat functionality and Comfy Fighter Z branding throughout the interface, workflows and documentation.
- The title screen reads Comfy Fighter Z with the subtitle Higgsfield Open Source Saga. Preserve the title, selection and two-fighter introduction flow; introTagline text and stock cloud voices come from the fighter configuration. Freeze combat during introductions and support skipping them.
- Keep local single-player versus CPU as the default. Also support invite-link online 1v1 and a shared display paired with one phone versus CPU or two phones versus each other. Each seat selects one fighter; keep the existing combat engine and its pose choreography (27 required key poses plus 18 optional arcade poses). Arrow keys move/jump/crouch; A punches, S kicks, D performs a heavy strike and F uses the one-button special. G taunts; A+S rolls, S+D blowback and F+D super. Combat follows gameplay-audit.md (branch `gameplay`, 2026-11-06): Capcom-style frame data (4-frame jab, S light kick, → + S roundhouse, ↓ + A/S/D crouching jab, low sweep and launcher; fixed hitstun and blockstun; rapid-fire jabs), pushback slides, 1000-point life with scaling after the third hit, meter only from contact and specials (a super's own hits build none), rectangle hit, hurt and limb boxes, committed jumps with a tucked jump box, a super jump (↓ then ↑, or ↑ after a launcher hit) into an A > S > D air chain with juggle decay, air resets, a CPU that blocks by height, confirms, punishes and anti-airs per level, and F by direction (neutral or back the shot, ↓ the rising strike, → the style special). `build/tools/gameplay-probe.cjs` and `build/tools/frame-data.cjs` measure it; `build/test/gameplay-metrics.test.cjs` holds the targets. Single player defaults to Arcade: a CPU ladder ending with the final boss, with continues, endings and high scores. Local Versus with gamepads and Training are also available. The engine stays deterministic for server-authoritative play: no `Math.random` in the simulation. Use a full-viewport arcade layout with native fullscreen available from a user gesture. Multiplayer simulation is server-authoritative, with combat frozen during introductions and disconnects. Export a bundled Node server so multiplayer and QR pairing work with `npm start` without installing dependencies in the exported game.

- The main `comfyui/workflows/comfy-hackathon.json` is the compact factory template: project settings, six character factories, a final-boss factory, three environment factories, shared UI/effects, the startup ensemble, the menu video, one fight introduction per fighter, a final mapped `assets.json` and `video.json`. Custom nodes expand into native cloud nodes to generate fictional source designs, identity references, individual 3x3 sheets, portraits, heroes, super cut-ins, ending art and stage art. Invent mode uses 104 paid image calls for the full arcade cast (100 with one environment); explicit Upload mode uses 94 (90). The classic set (`include_arcade_art` off, no boss, The Yard only) uses 57. Arcade art includes two optional motion sheets per fighter (`motionSheets` in `comfyui/config/game.json`: sheetF load, punchwhip, kickwhip, recoil, settle, stepin, stepout, dashload, dashpass; sheetG idle1–idle5, apex, land, kickrecoil, guardhit; `include_motion_art` on the character factory, two more 2K calls, `reference_sheet` chained from sheet A). The animation layer plays them as load → one-frame whip → held contact → recoil → settle on strikes, a six-cel breathing loop with eased holds (restarting from the neutral drawing via the engine's visual-only `standFrames`), a 24-frame stride with passing steps, a jump apex, a landing compression and a guard reaction; without them it falls back to the 45-pose set, never revisiting a wind-up cel after contact and holding one idle drawing instead of flipping two. The CLI `plan.json` pipeline and the arcade expansion keep the 45-pose layout; `new-game.cjs add-sheets` adds the motion sheets to an existing run. Optional detail sheets (`detailSheets` in `comfyui/config/game.json`: sheetH walkf1–walkf4, walkb1–walkb4, crouchdown; sheetI roll1–roll4, rollrise, sweepwind, sweepfull, sweepthrough, sweepback) give one fighter at a time drawn forward and backward walk cycles, a crouch transition, a five-frame roll and a four-frame sweep (`add-sheets --sheets sheetH,sheetI --fighters <id>`, $0.144 a fighter); the animation layer plays them when a fighter has the whole set and otherwise keeps the older stride, the single roll cel and the single sweep cel. Every canonical and Midterm Mayhem fighter carries them since 2026-11-07 (Griddle first, then the rest on the user's go-ahead). Review each new sheetH and sheetI as figure strips before merging (`build/tools/sheet-figures.mjs` counts figures; a sheet A with an extra figure biases its derived sheets, so redraw with `--reference-sheet sheetF`, or `sheetB` for sweeps; `build/tools/set-aside-sheets.cjs` makes room for a redraw and `assemble-sheet.cjs` builds a reviewed sheet from cells of earlier generations, recorded in the run's pipeline.json and the example provenance). Shared art includes a chroma-keyed menu frame (`ui/frame`) that the game uses for its dialogs. The static `arcade/` set is the original cast's own title art; every other game shows only its generated interface art. The game decides which from the manifest before anything paints, and a NOW LOADING boot screen covers the page until that art has loaded, so a game never flashes another game's art. The startup media add 15 image calls and 16 silent 720p LTX clips (86 seconds, about $11.81) for seven fighters: a clash-style title key art with an 8 s menu loop (`CFZTitleArt`, `CFZTitleVideo`), an 8 s select-screen loop from the shared select backdrop (`CFZSelectVideo`, mapped as `selectVideo`), a portrait six-second idle-stance loop per fighter (`CFZSelectIdleVideo`, mapped as `selectIdles` / `idle-<fighter>`) that the select cards play with a beat of stillness between loops, and four-second shonen-style fight introductions that the game plays side by side on a split screen. The split-screen introduction is the only pre-fight screen. `CFZSpriteSheet` accepts an accepted sheet as `reference_sheet`; the character factory chains sheet A into B–E. The builder normalizes standing-pose heights per sheet against the idle cel, processes fighter sheets at native resolution, honors a reviewed `mirror` list on sheet records and a reviewed `figures` map (pose → [x, y] sheet fractions) that picks each pose's figure where the model drew an extra one (a detached second whole figure is never merged into a cel; `build/tools/sprite-audit.cjs` and `sheet-figures.mjs` find such sheets), and draws the arena at device resolution. The arena is drawn by `build/public/render/`: the vendored PixiJS v8 renderer (`vendor/pixi.min.js`, MIT, shipped with every export) when WebGL initializes, otherwise the Canvas 2D renderer; the HUD and callouts always draw on the 2D overlay canvas. `?renderer=canvas` forces the fallback and `FighterDebug.renderer()` reports the active one. The Pixi path carries the impact layer: a world shader (chromatic aberration, radial blur, shockwave ring, negative flash on supers and KOs), camera punch-ins, additive glow sparks, auras, speed lines and stage desaturation on KO. The game ignores prefers-reduced-motion on purpose. The camera frames the fighters MvC-style (zoom 1.0–1.42 by distance and height, fighters about 42–59 % of the frame height, stage scaled about the floor) and contact pauses are 5/7/9 frames with 4 on a guard. Keep `engine.js` and `anim.js` renderer-agnostic; see `port-pixi.md`. The muted `comfyui/workflows/factory/arcade-expansion.json` adds the arcade material to an accepted classic bundle with 33 image calls. `comfyui/tools/prepare-duo-run.cjs` prepares a complete two-fighter run with every image, the media and the audio for cheap end-to-end checks. - Living stage scenery: `comfyui/workflows/factory/stage-scenery.json` (generated by `prepare-factory-workflows.cjs`, shipped muted until the accepted stage painting is uploaded) is one reproducible graph per stage. `CFZSceneDirector` (Gemini vision, token-priced, bounded by its output cap) plans the background additions and the effects on painted features. `CFZStageScenery` paints the additions in place and `CFZSceneIsolate` separates them onto chroma green (2K edits). `CFZExtractScenery` (local) cuts placed `layer` records and writes `scenery/<stage>.json`. - New games come from cast files (`comfyui/casts/*.json`, schema `comfy-fighter-cast/v1`, extending `comfyui/config/factory.json` for the art direction and sheet layout). `node build/tools/new-game.cjs prepare|run|review|reroll|export|install|status` is the whole pipeline: `prepare` prices the run (`comfyui/tools/prepare-cast-run.cjs`, which also builds the two-fighter run), `run` spends only with `--approve-usd` at or above the estimate and submits one paid node at a time, `review` writes contact sheets and flags for a person or an agent to read, `reroll` raises a node's `reroll` input (every paid factory and media node has one; it offsets the seed so only that node and its dependants redraw), `export` runs the strict bundle build (it refuses up front when the sources plus their runtime copies of clips and sounds cannot fit the builder's 1 GiB package limit, and names `pack-media`, which re-encodes clips above 12 Mbit/s as H.264 CRF 18 and WAV sounds as MP3 VBR q2, keeping the originals in `<run>/originals/`) and `install --slot <id>` places the game in `output/games/<id>`. `npm start` mounts every slot beside the main game and the server's `games.json` feeds the GAME SELECT screen on each title screen; a lone export hides it. Cast fighters and arenas are invented from text only: no real people, candidates, venues, party logos or flags — except a satire cast marked `"publicFigures": true` (user decisions 2026-11-05: `comfyui/casts/midterm-2026.json`, the Texas, Michigan and Kansas Senate winners versus their Republican opponents; 2026-11-08: `comfyui/casts/billionaires-brawl.json`, the six richest people in November 2026 with an invented final boss and invented arenas), which caricatures named public figures from short text descriptions only, never from photographs or recordings, uses stock synthetic voices, and keeps every line to public record or obvious arcade banter; the canonical cast and the included example stay fictional. The project settings node chooses the cloud video model for every clip (`video_model`: LTX-2.5 Fast at 720p, the template default, or Seedance 1.5 Pro at `video_resolution` 720p/1080p); cast files set it with `videoModel`/`videoResolution`, the reference casts use Seedance 1.5 Pro at 1080p (about $0.059/s, clean motion where LTX smears), and `reroll-art --video-model` moves an existing run's clips over. `comfyui/docs/new-game-runbook.md` is the agent-facing procedure; keep it current when the commands change.
- Crossover games put installed games in one roster without generating anything (user direction 2026-11-08: "create a combined game with all playable characters and levels", the Ultra game on branch `ultra-game`). A definition in `build/crossovers/` (schema `comfy-fighter-crossover/v1`; `ultra.json` is Comfy Fighter Z: Ultra Dream Match, combining the canonical runtime with the Rogue Protocol, Midterm Mayhem and Billionaires Brawl slots) and `node build/tools/crossover.cjs <definition>` (`npm run crossover`) compose the verified runtimes into `output/games/<slot>`: media from `output/` is hard-linked, tracked files are copied, every mapped file and clip digest is checked, and the slot is swapped in only when everything passes. Fighter and arena ids stay unique across games. Exactly one `finalBoss` keeps `boss: true`; the other games' bosses play as regular fighters with their boss moveset (labelled BOSS). Arcade tours `arcade.perSeries` rivals from each game in their own arenas, then the final boss in `bossStage`. `shared` supplies the announcer, menu music, sound effects and hit effects; `interface`, `ensemble` (a 2 x 2 key-art composite) and `titleMontage` (a title loop cut from each game's title art) set the presentation. A crossover with a satire source declares `publicFigures: true` and stays a separate slot, so the canonical cast and the included example remain fictional. The runtime reads `series`, `arcade` and `publicFigures` from the manifest and otherwise behaves as before; more than twelve fighters switch the select screen to one row per game with tiles sized to the screen. Rebuild the crossover after reinstalling a source game; `comfyui/docs/new-game-runbook.md` section 6 documents the fields.

- Phones get a lite presentation (user feedback 2026-11-09: the game "almost overheated the phone", the touch controller was "not great", and videos should autoplay after an initial press). `game.js` sets `window.CFZ_LITE` for a coarse pointer or four cores or fewer (`?lite=1`/`?lite=0` force it): both renderers cap the backing store at 1.25 device pixels per unit, the Pixi path takes a low-power context, skips the full-screen impact shader and paints the living scenery at 960x540 refreshed at 15 frames a second; the frame loop draws at most 60 times a second on any display; the select screen shows stills instead of the select loop and idle loops; and the boot screen ends on an ENTER THE GAME gate whose tap starts the title loop and unlocks audio. The touch controls are a floating thumb stick (drag past a dead zone: left/right walk, up jumps, down crouches, diagonals combine) and a diamond of A/S/D/F with ROLL and SUPER combo pills, each pointer captured by what it pressed. `build/deploy/README.md` is the procedure: `prepare-static-site.cjs` packages each verified export or installed crossover slot, `assemble-site-release.cjs` joins them into one release tree with hard-linked duplicates, `SHA256SUMS` and `release.json`, and `install-release.sh` verifies every checksum on the host, retains mounts the new release lacks (the phone-photo demo), installs the service and nginx files, switches the symlinks and checks every mount. Each mount needs its `ws`, `runtime-config.js`, `healthz` and `games.json` proxied and its folder listed in the service's `GAME_MOUNTS`. Credentials (`.env`, `*.pem`, `.mcp.json`) stay ignored; scan the history before pushing.
- The 90-second teaser (user direction 2026-11-09: "use comfyui, ffmpeg screen recordings for a 90 second teaser/explainer on this whole workflow and game outputs") is reproducible: `comfyui/config/teaser.json` (kind `teaser`: a fixed timeline with its own word bounds) is the storyboard; `comfyui/tools/prepare-explainer.cjs --config comfyui/config/teaser.json --out output/explainer/<run>` prices and writes the Eleven v4 narration graph (about $0.19 for eight scenes, submitted with `run-sequential.cjs`); the music bed is one `SoniloTextToMusic` node saved as `audio/teaser-music.flac` (90 s, $0.225); `build/tools/capture-teaser.cjs` records every scene from the local games, the run graph in the ComfyUI editor (writes intercepted, queue panel and wallpaper hidden, personal paths replaced) and cards drawn from the pipeline's own files; `build/tools/compose-explainer.cjs` cuts it with captions, a ducked continuous music bed (`music`/`musicLUFS`) and per-scene `captionText` where the voice spells an address.
